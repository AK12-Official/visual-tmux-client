## Why

运行参数分散在命令行、环境变量、Go 常量和前端常量中，无法用一份配置管理部署与运行行为。hub 的主包同时承载路由、tmux 操作、PTY/WebSocket 桥接和关闭流程，职责耦合使后续迭代及生命周期测试成本持续增加。

## What Changes

- 增加版本化 YAML 运行配置，统一默认值、严格解析、优先级、字段校验和来源记录；保留既有启动参数和环境变量。
- 外部化后端超时、票据、输入限制、输出背压及前端轮询、重连、终端和通知参数；通过公开白名单接口提供前端运行配置。
- 配置启动时读取，修改后重启生效；保持无配置启动和单二进制部署。
- 将 hub 拆分为入口、应用组装、配置、会话、认证、tmux、终端和传输模块，明确资源所有权，保持既有接口与终端行为。
- 更新构建入口、CI、发布脚本、示例配置和中英文说明。源码构建入口从 hub 根包迁至 `./cmd/visual-tmux-client`；发布二进制名称不变。
- 不引入热更新、多主机、通用插件系统、YAML 驱动的界面样式或前端全面重构。协议、安全不变量及构建工具配置继续由各自代码和标准文件管理。

- 加入 golangci-lint v2 质量门禁，统一本地与 CI 的规则，检查魔法数字、重复字符串、单行长度、函数长度、复杂度与常见正确性问题；完成现有代码整改后要求全量通过。

## Capabilities

### New Capabilities

- `runtime-configuration`: 集中 YAML 配置、兼容覆盖、校验、运行参数注入及浏览器白名单配置接口。

### Modified Capabilities

- `session-hub`: 将 YAML 来源纳入启动凭据展示和有效 Origin 策略描述，保留已有安全与会话行为。
- `web-session-manager`: 浏览器在启动时加载运行配置，并按服务端范围合并持久化字体偏好。

结构重组属于实现调整，不单独创建架构行为规格。通知参数的可配置性由 runtime-configuration 描述，既有通知等级、消失和堆叠行为保持兼容。

## Impact

- 涉及 `hub/*.go`、`hub/ringbuffer`、相关测试、`hub/web/src` 和新增 `hub/web/embed.go`；Go module 路径保持不变。
- 新增 `GET /api/client-config`，仅返回公开浏览器设置；既有 REST 路径、响应和 WebSocket 消息保持不变。
- 新增支持严格字段解码的 YAML 依赖；不引入通用配置框架。
- 更新 `Makefile`、`scripts/package.sh`、两份 GitHub Actions workflow、README 和配置示例。单二进制运行仍不依赖外部静态资源目录。
- 配置有误会在监听前拒绝启动；现有正常配置保持兼容。YAML 中的凭据遵循现有启动展示约定，但不进入配置接口、常规诊断或子进程环境。

- 新增根目录 `.golangci.yml` 与固定工具版本的安装入口，扩展 Makefile 和 CI；该文件属于开发工具配置，与应用运行 YAML 分离。质量门禁属于工程工具调整，不新增产品行为规格。
