# Visual Tmux Client v0.6.1

## 更新内容

- 新增 SOCKS5 代理设置，桌面应用和浏览器界面都可以用。在无法直连远程主机的网络下，点击顶栏“主机”旁边的“设置”，填入代理软件的地址并保存。之后到远程主机的每一条新连接都会经过这个代理，包括添加主机时检查服务器密钥、终端、文件操作和重连，服务器密钥照常校验。本地 tmux 不经过代理。
- 代理出问题时，界面会说明问题出在代理还是目标主机：代理连不上、代理要求账号密码、代理拒绝连接到主机、主机经代理没有回应。主机管理、会话列表和终端里都能看到对应的提示。
- 保存代理地址后新建的本地终端会话会带上 `http_proxy`、`https_proxy`、`all_proxy` 和 `no_proxy` 环境变量。读取这些变量的命令会走代理，例如通过 HTTPS 访问的 `git` 和 `curl`；`ssh` 和走 SSH 的 `git` 不受影响。自己 shell 配置里设置的代理变量优先生效。远程主机上的会话不带这些变量。
- 桌面应用新增应用图标，macOS 和 Linux 上都有。
- 顶栏、会话列表、主机管理和文件管理里的按钮、下拉框和输入框在中英文下保持相同尺寸和单行显示，切换语言时这些控件不再改变大小。

## 升级

备份现有可执行文件和私有状态目录，替换对应平台的二进制并重启应用。保留现有配置、启动参数与凭据。在同一配置下切换桌面与 headless 模式前，先退出当前进程以释放主机状态锁。

正式发布提供 Linux 和 macOS 的 amd64、arm64 headless 包与 SHA-256 校验和。桌面 DEB 和 macOS 应用包不在正式发布内，由 Desktop compatibility 工作流提供为开发构建，版本号为 `0.6.1-desktop.dev`。[桌面构建与运行指南](desktop.md)

回退到之前的版本时，已保存的代理地址会被忽略，应用像以前一样直接连接。

## 已知问题

- macOS 和 Linux 桌面应用长时间运行后可能逐渐失去响应。遇到该问题时，可退出桌面应用并使用原有服务器命令。[桌面运行与恢复说明](desktop.md#closing-and-recovery) · [问题记录](TODO.md#桌面应用)
- 代理设置只支持不需要账号密码的 SOCKS5 代理。HTTP 代理、按主机设置不同的代理、读取系统代理设置，以及 `~/.ssh/config` 里的 `ProxyJump` 和 `ProxyCommand` 均不支持。[代理说明](desktop.md#proxy-for-remote-hosts)
