## F1 / P1：批量终止会话会在切换主机后误杀另一主机会话

位置：`hub/web/src/App.vue:774-781`，关键行 779。

触发：A、B 都有 `one`、`two` 会话。在 A 批量删除两者，第一条 DELETE 尚未完成时切到 B。循环每次重新取 `currentHostId.value`，第二条请求发到 B，绕过用户原本对 A 会话的确认。

验证：直接提取 `onBulkKill` 函数，挂起第一条 mock killSession 后修改当前主机，再释放 Promise。记录结果为 `[{name:"one",host:"host-a"},{name:"two",host:"host-b"}]`。没有连接真实服务，也没有实际杀会话。

影响：B 的 tmux 会话及其运行进程可能被意外终止。

建议：操作开始时冻结 host ID 和连接版本；循环只对该目标执行，目标失效时终止。完成后的 UI 更新也必须按原 host 定位。增加 DOM 回归测试，批量操作过程中切换主机，断言所有 DELETE 仍指向原目标或明确取消。

同根因的相关路径：onCreate（639-641）、onRename（669 起）、onKill（750 起）在 await 后按当前主机修改选中项/终端身份；应一并检查，避免 A 完成响应更改 B 的视图和终端缓存。

## F2 / P1：迟到文件读取结果被标记为新主机文件

位置：`hub/web/src/components/files/FileManagerOverlay.vue:541`、`:562-572`。

触发：A 打开文本文件，readFile 正在等待时切到 B。返回内容来自 A，但新 OpenFile 的 hostId 和 revision 使用返回时的 props，故被标记为 B。

验证：直接提取并通过 Node stripTypeScriptTypes 执行现有 openFile，mock readFile 挂起；切换 host 后返回 `HOST A SECRET`。实际输出：请求为 `{operation:"read",p:"/secret.txt",h:"host-a"}`，新 tab 为 `{hostId:"host-b",path:"/secret.txt",text:"HOST A SECRET",revision:1}`。临时复现脚本 `/tmp/cr-web-repro.mjs`。

影响：A 内容出现在 B 身份的编辑器内；后续保存使用 tab.hostId，会发往 B。文件时间戳冲突可能拦截部分写入，但不能纠正身份，且用户可确认覆盖；同时间戳也可能直接满足保存条件。

建议：在异步操作入口冻结 host ID、版本及工作区代数；读取结果只进入原主机草稿，或切换后丢弃。opening、changes、树加载状态也应按 host 隔离。增加 A 慢读取、切 B、释放 A 响应的 DOM 测试，同时断言展示身份和后续保存 URL。

## F3 / P1：等待保存结束的删除请求会被重定向到新主机

位置：`hub/web/src/components/files/FileManagerOverlay.vue:1194-1198`；完成后的 tab 清理在 `:1213-1227` 也使用动态 host。

触发：A 的文件正在保存，用户确认删除该文件。deleteTarget 等待 `saving.idle(path, host.value)`；等待期间切到 B。等待完成后 deleteEntry 重新读取 host.value，于是删除 B 的同路径文件。

验证：直接提取现有 deleteTarget，mock saving.idle 挂起，切换 host 后释放 Promise。实际记录 `{operation:"delete",p:"/secret.txt",h:"host-b"}`。脚本同 `/tmp/cr-web-repro.mjs`。

影响：用户没有确认过的 B 文件可能被删除；删除完成后还可能移除 B 的未保存标签。同时 deleting.end 在新 host 清理标记，原 host 标记可能残留。

建议：删除全过程捕获原 host/连接版本；pending begin/end、等待、请求、tab 清理必须使用同一身份。增加“保存未返回 → 确认删除 → 切 B → 保存返回”测试，断言 B 无 DELETE 且草稿仍在。另一个无需等待保存的相关场景是：A 的 DELETE 已发送但响应晚到，切 B 后不能按 B 身份关闭同路径草稿。

## F4 / P1：删除最后一个主机会卸载编辑器并丢失未保存草稿

位置：`hub/web/src/App.vue:102-104`、`:889`、`:911`、`:1039`。

触发：只保留一个主机，打开文件并产生未保存修改；通过 Hosts 删除该主机。onHostDeleted 先标记 removed，然后 loadAvailableHosts 得到空列表，把 currentHostId 设为 null。模板转到 `availableHosts.length === 0` 空状态，原 `app__body` 以及 FileManagerOverlay 被卸载。

证据级别：静态控制流和 Vue v-if 生命周期核对，未做完整浏览器实测。FileManagerOverlay 的 tabs 保存在组件内部；没有上移或外部持久化。因此无法再按产品承诺保留草稿供复制。现有 active-host-removed 测试保留其他主机，不覆盖空列表分支。

影响：用户可能相信删除确认中“保留草稿”的行为，却失去所有打开的草稿。`filesDirty` 留在父组件也不能恢复已卸载的数据。

建议：将草稿存储移出条件渲染的工作区，或保证无主机状态仍挂载只读草稿面板。补充 App 集成测试，删除最后主机后断言草稿文字可见、可复制，所有远程保存操作不可用；同时覆盖其他浏览器删除最后主机后刷新发现列表为空的情况。
