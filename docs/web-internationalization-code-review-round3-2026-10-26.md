## 4. 剩余发现

### I18N-R3-01：会话列表刷新失败仍直接显示错误码

**级别：P2。状态：未修复。证据：代码路径审阅及组件 DOM 探针。**

位置：

- [App.vue:566](../hub/web/src/App.vue#L566)：`refresh()` 失败时将原始错误消息写入 `listError`。
- [SessionList.vue:320](../hub/web/src/components/SessionList.vue#L320)：无会话时直接展示 `error` 属性。
- 同组件的 stale 状态也应纳入修复检查，避免只处理空列表分支。

**触发条件：** 会话列表请求因主机不可达等原因失败，例如服务端返回 `host_unavailable`。

**复现方式：**

1. 将当前语言设置为 `zh-CN`。
2. 使用 `@vue/test-utils` 挂载 SessionList，传入空会话数组以及 `error: 'host_unavailable'`。
3. 读取 `.session-list__error` 的文本。
4. 同时检查 App 的实际调用路径，确认列表刷新失败时确实传入原始错误。

本轮探针输出：

```text
session error: host_unavailable重试
```

这是组件级复现，并非真实 SSH 断连实验。App 的静态调用链确认该组件输入与实际错误处理一致。

**实际行为与影响：** 中文界面仍显示裸错误码，重试按钮已经是中文。错误状态保存的是原始字符串，展示没有本地化映射，因此切换语言不会生成对应解释。主机不可达属于已知业务错误，可以提供清晰、可操作的说明。

**建议修复：**

- 继续保留原始错误码用于 `isRepairable`、停止轮询等业务判断。
- 在展示边界根据错误码生成当前语言的解释；不要将译文回写为业务判断依据。
- 未知错误提供本地化上下文并保留原始诊断。
- 一并检查主机发现、主机列表加载错误的相同展示方式。这些相邻路径本轮做了静态检查，没有逐个进行运行时复现，不另计问题数量。

**验收标准：**

- 空会话列表、已有缓存会话的刷新失败均有双语解释。
- 至少覆盖 `host_unavailable`、`host_not_found`、`host_revision_conflict` 及未知诊断。
- 错误可见时切换语言，消息更新，主机名、会话名及诊断内容保留。
- 重试、编辑主机、停止轮询和旧请求结果隔离等行为保持原有语义。

### I18N-R3-02：中文删除确认框仍插入英文类型名称

**级别：P3。状态：未修复。证据：代码路径审阅及组件 DOM 探针。**

位置：

- [FileManagerOverlay.vue:1480](../hub/web/src/components/files/FileManagerOverlay.vue#L1480)：将类型设为固定的 `directory` 或 `file`。
- [FileManagerOverlay.vue:1500](../hub/web/src/components/files/FileManagerOverlay.vue#L1500)：把该英文类型作为参数传入 `files.deleteEntryPrompt`。

**复现方式：**

1. 设置语言为简体中文。
2. 挂载文件管理器，用 fetch 替身返回工作目录 `/srv/work`，目录中包含文件 `a.txt`。
3. 调用组件暴露的 `deleteTarget()`，目标为 `/srv/work/a.txt`。
4. 使用 `window.confirm` 替身捕获提示并返回 false，避免执行删除。

本轮探针输出：

```text
delete prompt: 删除file“a.txt”？此操作无法撤销。
```

目录类型沿同一代码分支传入 `directory`，代码审阅确认也存在混用风险；本轮实际探针运行的是文件类型。

**根因与影响：** 外层确认句已本地化，但插值参数是应用生成的英文类型词，造成破坏性操作确认框中英混用。此问题没有改变确认结果或删除目标。

**建议修复：** 为文件与目录分别使用完整确认词条，或将类型参数本地化。不要翻译用户文件名。完整词条更便于未来支持语序或语法不同的语言。

**验收标准：**

- 两种语言分别验证文件、目录的删除确认。
- 中文不包含应用生成的 `file` 或 `directory`；英文语句自然。
- 文件名与目录名保持原文，未保存修改警告继续显示。
- 取消确认不发送删除请求，确认后的目标及并发保护逻辑保持原有行为。

## 6. 质量评价及建议

本轮修复比上一轮更完整：目录错误采用结构化状态，主机提交错误有集中映射，通知标签和能力标签直接使用词条，回归测试也验证了实际组件输出及语言切换。

建议优先完成 I18N-R3-01，再修 I18N-R3-02，补充能在当前实现上失败的定向回归测试，重新运行前端测试和构建后复核。修复仍位于未提交工作区，最终提交时应包含新增真实编辑器测试文件。
