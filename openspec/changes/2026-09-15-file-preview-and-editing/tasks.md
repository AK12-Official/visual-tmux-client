- [x] 4.2 Add `mapFileError` beside `mapSessionError`, mapping the error vocabulary to statuses (`invalid_path`/`invalid_body` 400, `path_not_allowed` 403, `not_found` 404, `conflict` 409, `file_too_large` 413, `dir_not_empty` 409, `permission_denied` 403, `write_failed` 500) while preserving the `{"error": "<code>"}` envelope. Verify: table-driven httptest asserting status and body code for each sentinel via a mock file service.
- [x] 4.3 Add the request/response DTOs to `dto.go` following existing conventions (unexported request structs, snake_case tags, `mtime` as integer milliseconds since the epoch). Verify: httptest decodes each response shape.
- [x] 4.4 Give the `write` handler its own `http.MaxBytesReader` bound derived from `files.max_file_size` rather than the global 64 KiB limit. Verify: httptest asserting a body just over the configured limit is refused with `file_too_large` while a body just under it succeeds.
- [x] 4.5 Add a `PaneWorkingDirectory` method to `hub/internal/tmux` using `Exec(ctx, "display-message", "-p", "-t", ExactTarget(name)+":", "#{pane_current_path}")`, and expose it as `GET /api/hosts/{hostId}/sessions/{name}/working-directory`. The trailing colon is load-bearing: `-t` takes a *pane* target, and a bare `=name` is only a session target -- tmux accepts it, resolves no pane, and prints an empty line with a zero exit status, which reads as "this session has no directory". Verify: unit test with a fake exec asserting the argument vector, and an httptest asserting an absent session maps to 404.
- [x] 4.6 Verify streaming headers: httptest asserting `read`/`download` set `Content-Length`, `X-File-Size`, `X-File-Mtime`, `Cache-Control: no-store`, and that `download` sets `Content-Disposition: attachment` while `read` does not.
- [x] 4.7 Have the hub classify a read as text or binary and say which, which the file-manager spec requires ("the hub SHALL allow the caller to distinguish binary content from text content"). This had no task in the original breakdown -- the frontend classified by extension alone, which is a guess, and a wrong guess either renders binary bytes as text or refuses to open a file that is text. `Read` samples a bounded prefix, reports `Binary`, and the `read` route carries it as `X-File-Binary`. A NUL byte is decisive; invalid UTF-8 is binary, tolerating only a rune split by the sample boundary. Verify: unit tests over text, UTF-8, empty, NUL-bearing, Latin-1, and extension-less files, plus the boundary cases in `binarySample`; an httptest asserting the header is present exactly when the contents are binary; and that sampling does not consume the stream.

operator against a real session -- on a hub confined to a throwaway directory, so
nothing under the operator's own files was at risk.

That pass earned its keep: it found three defects nothing automated had caught,
all of them in the component layer this repository's DOM-less test setup cannot
reach. The tree rendered nothing at all (a component referenced in a template but
never imported), a directory click could only expand and never become the current
directory, and stepping up out of the boundary replaced the listing with the
error instead of reporting it alongside. All three are fixed; the first is what
the flat `visibleRows` list replaced the recursive component with.
